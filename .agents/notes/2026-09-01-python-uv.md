# 决策：Python 侧工具链 uv 管理（2026-09-01）

已实施：是

## 问题
- tests/ 与 server/ 是长期维护的 Python 工具，需要可复现的依赖环境。
- 硬约束：朋友端无 pip/uv，`serve.py` 与启动链必须保持零依赖、系统 Python 直跑。

## 决策
- 根 `pyproject.toml`（name `ethereal-tarot`，kebab-case）+ `uv.lock` + `.python-version`（3.12.10）。
- `dependencies = []`（运行时零依赖，serve.py 不进入 uv 环境）；测试依赖 `playwright>=1.60.0` 放 dev 组。
- 开发者跑测试：`uv sync` → `uv run python tests/run_e2e.py ...`；`serve.py` 与 `Click Me.bat` 仍用系统 Python 直跑。
- 前端依赖仍归 npm（package.json），pyproject 只管 Python 侧；两套 lock 并存，边界清楚。

## 替代方案（强制）
- 全局 pip 装 playwright：版本不可复现，换机器/换项目互相污染。
- rich/click 等进 pyproject：运行时无需求，测试用不到，维持依赖最小。
- 前端也迁 uv（uv 可管理 Node 依赖）：变更面大、与 npm scripts 生态重复，无收益。

## 影响
- 测试环境可复现（uv.lock 锁定）；朋友端体验零变化（不依赖 uv、不依赖 .venv）。
