# 决策：启动器轻量版先行，Rich 完整版待迁移完成后（2026-09-01）

已实施：是（轻量版 serve.py + 完整 Rich 版，2026-09-01 于独立分支 feat/rich-launcher 落地）

## 问题
- 原 `Click Me.bat` 用 `start /b` + 固定端口 8000：端口被占用即失败、关窗口可能残留 python 进程、dist 过期无提示。

## 决策
- 立即实施轻量版 `server/serve.py`（纯标准库，零依赖）：端口自动顺延（8000→8001…）、同进程 `ThreadingHTTPServer`（关窗口/Ctrl+C 即退出，零残留）、dist 缺失报错、manifest 式过期提示（src/public mtime > dist mtime 时警告不阻断）。
- `Click Me.bat` 改为调用它；朋友包新增 `server/serve.py` 一个文件，无需任何新依赖。
- 完整 Rich 版（core/ui 分层 + SHA-256 指纹 + 面板交互）是迁移完成后的独立任务，已记入根 AGENTS.md 待办；其 dist 过期指纹机制届时再评估（mtime 对比已覆盖 95% 场景）。

## 更新（2026-09-01 维护者决定）
- 完整 Rich 版**已实施**（分支 `feat/rich-launcher`）：core/ui 分层 + 根 `launcher.py`。
- core/（零 Rich 依赖）：config / integrity（三指纹 + 元数据判定）/ builder / server（同进程零残留）。
- ui/：theme / spinners / prompts / dashboard。
- 元数据 `.ethereal-meta.json` 放项目根：Vite emptyOutDir 会清空 dist，放 dist 内判定将永远失效。
- 朋友路径保持零依赖（`serve.py` + `Click Me.bat` 不变）；launcher 仅服务开发者（双击入口 `Rich Launcher.bat`，或 `uv run python launcher.py`）。
- 同步完成：core/ui/server 双件、根 README 入口、ARCHITECTURE 分层、根 AGENTS 命令与待办。

## 替代方案（强制）
- Rich 完整版现在就上：约 10 个新文件 + `rich` 依赖，朋友端无 pip/rich 将无法启动；开发者已有 npm scripts，属于第三套平行入口，时机未到。
- subprocess 托管 http.server + CTRL_BREAK 清理：复杂度高于同进程 ThreadingHTTPServer，且无法覆盖"直接关窗口"场景，放弃。

## 影响
- 朋友与开发者共用同一入口；零新依赖；退出无残留已由测试验证（kill 后端口释放）。
